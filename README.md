# Bili On-Demand Subtitles

> Local-first, on-demand subtitles for Bilibili videos without captions — generated by a Whisper service on your own machine and kept entirely in your browser's local storage.

Browser extension (Manifest V3) + optional local speech-recognition service. Open a Bilibili video that has no subtitles → click the **Subtitle** pill → subtitles are generated and stay in sync with playback automatically. Results are persisted, manageable, and exportable as `.srt`.

**Status:** extension `v0.5.1` · portable local service `v0.5.2` · tested on 64-bit Windows 10/11 (service) + Chrome/Edge (extension).

> Demo GIF / screenshots: see [`docs/demo.md`](docs/demo.md) for what to record and where to drop the files.

## Why this design

Getting clean audio out of Bilibili inside a browser is the hard part: media URLs are signed and reject plain `fetch` calls (Referer / hotlink protection). This project sidesteps that in two layers:

```
video page (sub-ui.js)
   │  click "Generate" → sends the __playinfo__ audio URL to the offscreen page
   ▼
offscreen page (offscreen.js) ──local service preferred──▶ subtitle-server.py
                                 service downloads the audio itself
                                 (proper Referer + UA, bypasses browser fetch limits)
                                 → faster-whisper transcribes the full clip
                                 → subtitle JSON stored in chrome.storage
                           └──service unavailable──▶ in-browser fallback:
                              browser downloads audio → WASM whisper (slower)
   ▼
subtitle library (library.html): list / delete / export .srt
   storage: chrome.storage.local (unlimited, survives restarts)
```

The extension always probes the local service first (`/health`). If it is not running, the service can be **auto-launched through a Native Messaging host** (`subtitle-native.exe`) and shuts down when the browser closes; without a host, the extension falls back to in-browser WASM transcription.

## Features

- ⚡ **Local-first transcription** — audio never leaves your machine; no API keys, no per-minute fees
- 🎯 **Accurate timing for playback sync** — monotonic progress reporting, seek-tolerant subtitle overlay (fullscreen included)
- 💾 **Persistent subtitle library** — stored per video (`sub:<cid>`), list / delete / export `.srt` from a dedicated page
- 🔁 **Two recognition paths** — fast local service (faster-whisper `small`, int8) with an in-browser WASM fallback
- 🔌 **Zero-install auto-launch** — Native Messaging host starts/stops the local service with the browser (optional, one-time setup)

## Quick start

### 0. One-time vendor restore (required after cloning)

The ~23 MB WASM runtime is **not stored in git**. After cloning, run:

```bash
python tools/fetch_vendor.py     # restores extension/transformers.js + extension/ort/*
python tools/fetch_vendor.py --check   # verify
```

### 1. Local recognition service (recommended)

**Option A — portable, no Python needed (end users).** Download the latest portable zip from [Releases](...) (built by `tools/build_package.py`), unzip anywhere, then either double-click `启动字幕服务.bat` or run the `安装-浏览器自动拉起.bat` installer once so the browser auto-starts the service.

**Option B — from source (developers).** Requires Python 3.10+ with the deps from `subtitle-server.py` (faster-whisper, ctranslate2, flask, av, opencc). First run downloads the small model (~460 MB):

```bash
python subtitle-server.py        # wait for "Running on http://127.0.0.1:8765"
```

### 2. Load the extension

1. Open `edge://extensions` (or `chrome://extensions`) → enable **Developer mode** → **Load unpacked** → select the `extension/` folder.
2. *(Optional, browsers auto-launching the service)* run the installer script in the portable folder and paste the extension ID.
3. Open any caption-less Bilibili video → bottom-left **Subtitle** pill → **Generate** → wait for progress to finish.
4. Play: subtitles sync automatically, track seeking, and show in fullscreen.

> Without the local service the WASM fallback runs but is ~3× slower and the service-less download path is the least-tested combination (see [Known limitations](#known-limitations)).

## Repository layout

```
extension/          MV3 extension source (load unpacked from here)
  shared-subs.js      pure functions: SRT parse/generate, timestamp lookup
  sub-ui.js           video-page pill + panel + playback overlay
  offscreen.js        job orchestration (service first, WASM fallback), progress
  background.js       job scheduling, keep-alive, exports, library entry
  library.html/js     subtitle library manager
subtitle-server.py  local Flask recognition service (127.0.0.1:8765)
tests/              regression suites (server + shared JS)
tools/
  build_package.py    builds the offline portable zip (engine + model + host)
  fetch_vendor.py     restores the WASM runtime not stored in git
  native_host.cs      Native Messaging host source (auto-launch)
docs/               architecture notes, Chinese README, demo assets
```

## Testing

```bash
python tests/test_server.py     # server: in-process Flask routes + real transcription (needs the model, ~1–3 min)
node tests/test_shared.js       # shared JS pure functions (8 tests)
```

Both suites are also wired into `tests/run_all.bat` on Windows.

## Known limitations

- Recognition speed ≈ local faster-whisper speed (roughly real-time on a mid-range CPU); the in-browser WASM fallback is ~3× slower
- `whisper small` occasionally confuses homophones in Chinese
- Scope is Bilibili web video pages; other sites are not targeted
- The service-less (pure WASM) path has not been re-validated end-to-end after the last refactor — treat it as a best-effort fallback
- Store listing (Edge/Chrome) is not yet pursued
